# Руководство разработчика

## Требования

- Node.js 22.13 или новее;
- Chrome/Edge для ручной проверки File System Access API;
- тестовая папка без ценных оригиналов для сценариев записи и переноса.

## Перед изменениями

```bash
npm install
npm run verify
```

## Правила

1. Не изменяйте `BackUp/Ver1 - PC_ver_only` — это защищённый исторический снимок.
2. Синхронно обновляйте `PhotoDate.html`, `start.html` и `public/PhotoDate.html`.
3. Не добавляйте внешнюю загрузку пользовательских фотографий.
4. Любая операция удаления или перезаписи должна иметь подтверждение и понятную ошибку.
5. Не перекодируйте JPEG без необходимости: это ухудшает качество и может менять ориентацию.

## Проверка pull request

```bash
npm run verify
npm run build
npm run lint
```

Ручной smoke-test:

1. Открыть тестовую папку с JPG и MP4.
2. Проверить сортировку и переход между папками.
3. Изменить дату у двух файлов и проверить EXIF после повторного открытия.
4. Перенести выбранные файлы в соседнюю папку.
5. Нажать «Вернуть прошлый ход» для переноса и даты.
6. Убедиться, что конфликт имён не перезаписывает файл.

## Коммиты

Предпочтительны небольшие содержательные коммиты в повелительном наклонении: `Add EXIF regression test`, `Fix folder scroll restoration`.
