# Архитектура

## Обзор

Multi Photo Change Date построен как local-first приложение. Рабочее ядро упаковано в автономный HTML-файл и не зависит от сервера во время обработки медиатеки.

```text
Пользователь
    │
    ▼
Галерея и дерево папок
    │
    ├── File System Access API ──► чтение/перезапись/перенос файлов
    ├── EXIF pipeline ───────────► JPEG APP1 + DateTimeOriginal
    ├── Video pipeline ──────────► ISO BMFF mvhd/mdhd timestamps
    └── Undo history ────────────► возврат дат и расположения
```

## Независимые части

### 1. Автономное приложение

Читаемые исходники находятся в `src/standalone/`: HTML-разметка, независимые слои CSS и JavaScript-файлы по зонам ответственности. Скрипт `scripts/build-standalone.mjs` объединяет их в `start.html`, `PhotoDate.html` и `public/PhotoDate.html`. Пользователь по-прежнему может скачать один файл и запустить приложение без Node.js, сервера и установки пакетов.

### 2. Метаданные изображений

JPEG обрабатывается на уровне бинарных APP1/EXIF-сегментов. Приложение записывает три согласованных временных поля и сохраняет ориентацию изображения. При повторном открытии дата берётся из EXIF, а `lastModified` используется только как fallback.

### 3. Метаданные видео

MP4/MOV/M4V обрабатываются как ISO Base Media File Format. Редактор обновляет creation/modification timestamp в атомах `mvhd` и `mdhd`, не перекодируя медиапоток.

### 4. Файловые операции

На ПК File System Access API предоставляет handles каталогов и файлов. Перенос выполняется в порядке «проверка конфликтов → создание копии → удаление источника». Перед операцией требуется подтверждение.

### 5. Web-оболочка

`app/` и `worker/` — тонкий слой для HTTPS-деплоя. Он не получает содержимое пользовательских фотографий и перенаправляет на статический bundle из `public/`.

### 6. Проверки

`scripts/verify-standalone.mjs` компилирует каждый inline-script через Node VM и проверяет наличие критичных функций. `tests/standalone.test.mjs` защищает продуктовые сценарии от случайного удаления.

## Компромиссы

- автономный bundle удобен пользователю, но сложнее для модульного анализа;
- браузер не позволяет программно сохранить iPhone-файл прямо в медиатеку без системного share sheet;
- системное время изменения файла после записи контролируется браузером, поэтому источником истины служит EXIF;
- история undo живёт только в текущей вкладке и намеренно не копирует фотографии в память сверх необходимого.

## Направление развития

Следующий безопасный шаг — вынести исходный код в ES-модули и генерировать автономный bundle на этапе сборки, сохранив однофайловый пользовательский дистрибутив.
